## R10.1 — Eliminare voce WiFi config al primo boot (no SSID salvato)

### Problema

Quando il device non ha SSID salvati, al boot chiama `TryWifiConnect()` → `StartWifiConfigMode()` che riproduce `OGG_WIFICONFIG` ("entra nella modalità di configurazione WiFi"). Per un utente nuovo è confusionario — il device dovrebbe entrare silenziosamente in AP mode e mostrare istruzioni sul display.

### Analisi codice

**File**: `Note/main/boards/common/wifi_board.cc`

```
TryWifiConnect() (riga 91-106):
  → no SSID → delay 1500ms → StartWifiConfigMode()

StartWifiConfigMode() (riga 161-206):
  → SetDeviceState(kDeviceStateWifiConfiguring)
  → wifi_manager.StartConfigAp()
  → SetBootStatus("Connettiti a: <SSID>")
  → Alert(..., OGG_WIFICONFIG)   ← QUESTO riproduce la voce
```

L'`Alert()` (riga 184) suona `OGG_WIFICONFIG` **sempre** — sia al primo boot che dopo timeout di connessione.

### Piano implementazione

**Approccio**: Non suonare `OGG_WIFICONFIG` quando non ci sono SSID salvati (primo boot). Suonare solo dopo timeout connessione (60s).

**Modifiche**:

1. **`wifi_board.h`** — aggiungere flag `bool first_boot_no_ssid_ = false;`

2. **`wifi_board.cc:TryWifiConnect()`** — settare il flag:

   ```cpp
   if (have_ssid) {
       first_boot_no_ssid_ = false;
       // ... connect
   } else {
       first_boot_no_ssid_ = true;  // ← NUOVO
       vTaskDelay(pdMS_TO_TICKS(1500));
       StartWifiConfigMode();
   }
   ```

3. **`wifi_board.cc:StartWifiConfigMode()`** — skip Alert se primo boot:

   ```cpp
   // Mostra sempre hint sul display (boot screen)
   AdaUiManager::GetInstance().SetBootStatus(ada_hint.c_str());

   // Suona voce SOLO se non è primo boot senza SSID
   if (!first_boot_no_ssid_) {
       Application::GetInstance().Schedule([&wifi_manager]() {
           // ... Alert con OGG_WIFICONFIG
       });
   }
   first_boot_no_ssid_ = false;  // reset flag
   ```

### File coinvolti

| File            | Modifica                                                     |
| --------------- | ------------------------------------------------------------ |
| `wifi_board.h`  | `bool first_boot_no_ssid_`                                   |
| `wifi_board.cc` | Flag in `TryWifiConnect()`, guard in `StartWifiConfigMode()` |

### Verifica

- [ ] Primo boot (no SSID): display mostra "Connettiti a: aDa_XXX", **nessuna voce**
- [ ] Timeout connessione (60s): voce `OGG_WIFICONFIG` riprodotta normalmente

## R10.3 — WiFi disconnect → auto AP mode

### Problema

Attualmente quando il WiFi si disconnette (`HandleNetworkDisconnectedEvent`), il device:

- Chiude l'audio channel
- Aggiorna la status bar
- **Rimane in idle** — non rientra in AP mode

L'utente deve fare factory reset o reboot per riconfigurare il WiFi.

### Analisi codice

**`application.cc:286-298`** — `HandleNetworkDisconnectedEvent()`:

```cpp
void Application::HandleNetworkDisconnectedEvent() {
    auto state = GetDeviceState();
    if (state == kDeviceStateConnecting || ...) {
        protocol_->CloseAudioChannel();
    }
    display->UpdateStatusBar(true);
    // ← FINISCE QUI — nessun tentativo di riconnessione o AP mode
}
```

Il timeout esiste solo per la connessione iniziale (60s), non per disconnessioni successive.

### Piano implementazione

**Flusso desiderato:**

1. WiFi disconnette → timer 30s di riconnessione automatica
2. Se riconnette entro 30s → tutto ok
3. Se NON riconnette entro 30s → `EnterWifiConfigMode()` (AP mode)

**Modifiche**:

1. **`wifi_board.h`** — aggiungere:

   ```cpp
   esp_timer_handle_t reconnect_timer_ = nullptr;
   bool was_connected_ = false;
   static void OnWifiReconnectTimeout(void* arg);
   ```

2. **`wifi_board.cc` constructor** — creare timer:

   ```cpp
   esp_timer_create_args_t reconnect_args = {
       .callback = OnWifiReconnectTimeout,
       .arg = this,
       .name = "wifi_reconnect_timer",
   };
   esp_timer_create(&reconnect_args, &reconnect_timer_);
   ```

3. **`wifi_board.cc:OnNetworkEvent()`** — gestire disconnect/reconnect:

   ```cpp
   case NetworkEvent::Connected:
       esp_timer_stop(reconnect_timer_);  // annulla timer reconnect
       was_connected_ = true;
       // ... resto invariato

   case NetworkEvent::Disconnected:
       if (was_connected_ && !in_config_mode_) {
           ESP_LOGW(TAG, "WiFi lost, starting 30s reconnect timer");
           esp_timer_start_once(reconnect_timer_, 30 * 1000000ULL);
       }
       break;
   ```

4. **`wifi_board.cc`** — callback timeout:
   ```cpp
   void WifiBoard::OnWifiReconnectTimeout(void* arg) {
       auto* board = static_cast<WifiBoard*>(arg);
       ESP_LOGW(TAG, "WiFi reconnect timeout, entering AP config mode");
       WifiManager::GetInstance().StopStation();
       board->StartWifiConfigMode();
   }
   ```

### Edge cases

| Scenario                             | Comportamento                                          |
| ------------------------------------ | ------------------------------------------------------ |
| WiFi drop momentaneo (router reboot) | Riconnette entro 30s → ok                              |
| WiFi sparito (fuori range)           | 30s → AP mode                                          |
| In sleep quando WiFi cade            | Modem sleep mantiene connessione; se cade, timer parte |
| Già in AP mode                       | `in_config_mode_` guard → non ritriggera               |
| Primo boot senza SSID                | `was_connected_ = false` → nessun timer                |

### File coinvolti

| File            | Modifica                                          |
| --------------- | ------------------------------------------------- |
| `wifi_board.h`  | `reconnect_timer_`, `was_connected_`, callback    |
| `wifi_board.cc` | Timer create, callback, guard in `OnNetworkEvent` |

### Verifica

- [ ] Spegnere router → 30s → device entra in AP mode
- [ ] Spegnere router → riaccendere entro 30s → device riconnette senza AP mode
- [ ] Primo boot senza SSID → AP mode immediata (nessun timer)

## R10.4 — Sleep via voce/chat ("dormi")

### Problema

Il device va in sleep solo tramite:

- Timer inattività 30s (R6)
- Long-press bottone 5s (R3)

Serve poter dire "dormi" via voce o dalla chat UI, e il device entra in sleep mode.

### Analisi

Il sleep è gestito nel board SenseCAP Watcher: `EnterSleepMode()` in `sensecap_watcher.cc:128`. Non è esposto come MCP tool né come comando WS.

### Piano implementazione

**Due componenti:**

#### A) Firmware: MCP tool `self.system.sleep`

**File**: `Note/main/boards/sensecap-watcher/sensecap_watcher.cc`

Aggiungere in `InitializeTools()`:

```cpp
// Tool: self.system.sleep
mcp.AddTool("self.system.sleep",
    "Put the device to sleep. Display turns off, WiFi enters modem sleep.",
    PropertyList(),
    [this](const PropertyList& properties) -> ReturnValue {
        ESP_LOGI(TAG, "Sleep via MCP tool");
        EnterSleepMode();
        return true;
    });
```

A differenza del factory reset, qui la risposta MCP arriva **prima** del sleep (non c'è reboot), quindi nessun timeout.

#### B) Gateway: tool TypeScript `laragoci_sleep`

**File**: `extensions/xiaozhi/src/tools.ts`

```typescript
api.registerTool({
  name: "laragoci_sleep",
  label: "Ada Sleep",
  description:
    "Metto il dispositivo in modalità sleep. Il display si spegne e consumo meno energia. L'utente può dire 'dormi' o 'vai a dormire'.",
  parameters: Type.Object({}),
  async execute(_id, _params) {
    const bridge = getBridge();
    if (!bridge) return notConnected();
    try {
      const result = await bridge.callDeviceMcp("tools/call", {
        name: "self.system.sleep",
        arguments: {},
      });
      return ok({ ok: true, result });
    } catch (err) {
      return ok({ ok: false, error: String(err) });
    }
  },
});
```

### File coinvolti

| File                                     | Modifica                                            |
| ---------------------------------------- | --------------------------------------------------- |
| `sensecap_watcher.cc`                    | MCP tool `self.system.sleep` in `InitializeTools()` |
| `extensions/xiaozhi/src/tools.ts`        | Tool `laragoci_sleep`                               |
| `Note/plans/Guide/MCP_Hardware_Tools.md` | Aggiornare tabella                                  |
